# Weaverse for Next.js

`@weaverse/hydrogen/next` is the Weaverse adapter for the Next.js App Router, an entry point of the `@weaverse/hydrogen` package. It renders Weaverse pages in a Next storefront, connects them to Weaverse Studio for visual editing, and runs your section loaders on the server.

<Note>
  `@weaverse/next` is deprecated in favour of `@weaverse/hydrogen/next` and `@weaverse/hydrogen/next/server`. From `@weaverse/hydrogen` 6.2.0 the Next.js adapter ships inside `@weaverse/hydrogen`, which no longer depends on `@weaverse/next`. To move a storefront off it, remove `@weaverse/next` from `package.json`, install `@weaverse/hydrogen`, and run `npx @weaverse/cli@latest migrate v6` to rewrite the imports. See the [v6 migration guide](/migration-advanced/v6-migration#step-2-run-the-weaverse-codemod).
</Note>

A Next.js storefront is still a Shopify Hydrogen storefront. [Hydrogen](https://github.com/Shopify/hydrogen) is Shopify's framework-agnostic toolkit for headless commerce, and the React Router template is only one way to use it: the Hydrogen README lists [Vercel Shop](https://github.com/vercel/shop), a Next.js storefront built on Hydrogen and maintained by Vercel, alongside it. Each layer owns one job:

- **Shopify owns commerce.** Products, collections, cart, checkout, customer accounts and markets come from your store through the Hydrogen SDK (`@shopify/hydrogen`) and the Storefront API.
- **Next.js owns the app.** Routing, Server Components, caching and metadata.
- **Weaverse owns the pages.** Sections, theme settings, translations and visual editing in Studio.

## React Router or Next.js?

Both are Hydrogen storefronts on Shopify, so your component schemas, input settings and theme settings work the same way. `@weaverse/hydrogen` ships one adapter per framework as an entry point; pick the one your storefront runs on:

- **`@weaverse/hydrogen/react-router`** for the Hydrogen React Router framework, for example a storefront deployed to Oxygen. The package name predates Hydrogen becoming framework-agnostic.
- **`@weaverse/hydrogen/next`** for the Next.js App Router, for example a storefront deployed to Vercel.

What changes is how the framework hands Weaverse a request and renders the page:

| | `@weaverse/hydrogen/react-router` (React Router) | `@weaverse/hydrogen/next` (Next.js) |
| --- | --- | --- |
| Server client | `context.weaverse`, injected into every route loader | Created by your app per request with `createWeaverseNextServerClient()` |
| Component registry | One registry | A client registry (rendering) and a server registry (schemas and loaders), split by React Server Components |
| Root theme store | `withWeaverse()` around the root | `WeaverseNextRootProvider` in `app/layout.tsx` |
| Page rendering | `WeaverseHydrogenRoot` in a route | `WeaverseNextRenderer` inside a client boundary |
| Loader revalidation | React Router `shouldRevalidate` | A route handler created with `createWeaverseNextRevalidateHandler()` |
| Routes | Shopify URL convention | Any routes your app serves; declare the ones that differ in the theme schema's `routes` |

## Requirements

- A Shopify store with Storefront API access from the [Headless channel](https://shopify.dev/docs/storefronts/headless/building-with-the-storefront-api/manage-headless-channels): a private token for server reads, and the public token Studio uses to open default templates (see [Studio integration](/nextjs/studio)).
- A Next.js App Router app that reads from Shopify, typically through the Hydrogen SDK (`npx @shopify/hydrogen@latest setup`). Peer dependencies: `next >= 14`, `react >= 19`, `react-dom >= 19`.
- `@weaverse/hydrogen` 6.0.0 or later, which needs `@shopify/hydrogen` 2026.10.0 or later as a peer dependency.
- A Weaverse project.

<Note>
  [Forward](/hydrogen-themes/forward), the Weaverse Next.js starter theme, runs in production on `@weaverse/hydrogen/next` with Next.js 16, React 19 and the Hydrogen SDK (preview).
</Note>

## What 1.0 supports

- **Page rendering**: home, product, collection, all products, page, article and custom pages, with section loaders on the server.
- **Studio editing**: connect, select, edit and reorder sections in Weaverse Studio, with live theme settings.
- **Per-item revalidation**: a resource picker edit re-runs only that section's loader. See [Studio integration](/nextjs/studio).
- **Theme settings**: one root store shared by global components (header, footer) and every page.
- **Markets and translations**: localized pages per market and the Translation Manager. See [Markets & translations](/nextjs/markets-translations).
- **Custom pages and SEO**: custom pages, sitemap data, and page SEO mapped to Next `Metadata`. See [Rendering pages](/nextjs/rendering-pages).
- **Theme routes**: tell Studio which paths your storefront uses when they differ from Shopify's.

## Known limitations

- **`publicEnv` in the root layout.** The SDK attaches `publicEnv` to the theme settings response only in design mode, which it reads from `?isDesignMode=true`. A Next layout receives no search params, so pass `publicEnv` to `WeaverseNextRootProvider` yourself. Studio needs `PUBLIC_STORE_DOMAIN` and `PUBLIC_STOREFRONT_API_TOKEN` from it to open your store's default product, collection and page.
- **Shopify redirects and request handling** are part of your app, not the SDK. Add the redirects your storefront needs in `next.config` or your proxy.

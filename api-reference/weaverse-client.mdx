# WeaverseClient

`WeaverseClient` loads Weaverse page data, theme settings, and custom page metadata on the server. It also runs registered component loaders and integrates with Hydrogen caching.

## Initialization

Create the client once per request in your app context, from the request's Hydrogen 2026.10 Storefront API client. Pilot does this in `app/.server/context.ts`:

```tsx
import { WeaverseClient } from '@weaverse/hydrogen/react-router'

export async function createAppContext(
  request: Request,
  env: Env,
  executionContext: ExecutionContext
) {
  const waitUntil = executionContext.waitUntil.bind(executionContext)
  const [cache, session] = await Promise.all([
    caches.open('hydrogen'),
    AppSession.init(request, [env.SESSION_SECRET]),
  ])
  const storefront = createRequestStorefront({ request, env, cache, waitUntil })
  const customerAccount = createCustomerAccount({ env, request, session, storefront })

  const weaverse = new WeaverseClient({
    storefront,
    env,
    cache,
    waitUntil,
    request,
    customerAccount, // Optional: passed through to section loaders
    themeSchema,
    components,
    // Optional: the market's public locale, when it differs from `storefront.locale`
    locale: resolveRequestLocale(request),
    // Optional: override env-based project resolution
    projectId: env.WEAVERSE_PROJECT_ID,
    // Optional: request timeout in milliseconds
    fetchTimeoutMs: 10_000,
    // Reject with WeaverseLoadError on a failed load instead of resolving to null
    throwPageLoadFailures: true,
  })

  return { env, cache, waitUntil, session, storefront, customerAccount, weaverse }
}
```

`createRequestStorefront`, `createCustomerAccount`, `AppSession` and `resolveRequestLocale` are app code; see [Step 4 of the v6 migration guide](/migration-advanced/v6-migration#step-4-build-the-app-context-yourself). `server.ts` copies the returned object onto React Router's context, so loaders read `context.weaverse`.

See the [Project Structure guide](/intro/project-structure#essential-files) for the complete setup.

## Public API

```typescript
class WeaverseClient {
  constructor(args: WeaverseClientArgs)

  API: 'v1'
  basePageConfigs: Omit<WeaverseProjectConfigs, 'requestInfo'>
  basePageRequestBody: Omit<FetchProjectRequestBody, 'url'>
  configs: WeaverseProjectConfigs
  storefront: WeaverseClientArgs['storefront']
  customerAccount: WeaverseClientArgs['customerAccount']
  env: WeaverseClientArgs['env']
  cache: WeaverseClientArgs['cache']
  waitUntil: WeaverseClientArgs['waitUntil']
  request: WeaverseClientArgs['request']
  components: WeaverseClientArgs['components']
  themeSchema: WeaverseClientArgs['themeSchema']

  fetchWithCache<T>(
    url: string,
    options?: WeaverseFetchWithCacheOptions
  ): Promise<T>
  fetchCustomPages(options?: FetchCustomPagesOptions): Promise<CustomPageEntry[]>
  loadThemeSettings(strategy?: CachingStrategy): Promise<WeaverseThemeSettingsResponse>
  loadPage(params?: LoadPageParams): Promise<WeaverseLoaderData | null>
  execComponentLoader(item: WeaverseComponentData): Promise<WeaverseComponentData>
  generateFallbackPage(message: string): WeaversePageData
}

type WeaverseClientArgs = {
  storefront: WeaverseStorefront // Hydrogen 2026.10 Storefront API client
  locale?: WeaverseI18n // defaults to `storefront.locale`
  env: WeaverseEnv
  waitUntil?: (promise: Promise<unknown>) => void
  customerAccount?: unknown
  components: WeaverseComponent[]
  themeSchema: WeaverseThemeSchema
  request: Request
  cache: CacheInstance
  projectId?: string | (() => string) | (() => Promise<string>)
  fetchTimeoutMs?: number
  throwPageLoadFailures?: boolean
}
```

- `locale` selects the content locale, the Translation Manager overrides (`${language}-${country}`, lowercased) and the locale Studio reads, so include `pathPrefix`. Pass it when the Storefront client's `locale.language` is a Shopify `LanguageCode` that differs from the market's public language, such as `ZH_TW` for a Traditional Chinese Hong Kong market. Added in `@weaverse/hydrogen` 6.1.0.
- `throwPageLoadFailures: true` makes `loadPage()` reject with a [`WeaverseLoadError`](/api-reference/weaverse-load-error) when a load fails (API unavailable, invalid response, or a configuration error such as a missing project ID), instead of resolving to `null`, so a route can answer an outage differently from a missing page. A 404 from the Weaverse API still resolves to `null`.
- `projectId` overrides the env-based project. A function must be synchronous: an `async` function, or one that returns a promise, throws a `WeaverseError` with code `ASYNC_PROJECT_ID` when the client is created. Resolve the ID first and pass the result, for example `projectId: await resolveProjectId(request)`. The published type still lists `() => Promise<string>`, but the runtime rejects it. (The Next.js server client does await an async resolver; see the [Next.js SDK reference](/nextjs/api-reference).)

`API` is the current API version segment (`'v1'`), not a complete endpoint URL.

## Methods

### `fetchWithCache`

Fetch data through Hydrogen's cache integration:

```typescript
fetchWithCache<T>(
  url: string,
  options?: RequestInit & {
    cacheTarget?: BuilderApiCacheTarget
    strategy?: CachingStrategy
  }
): Promise<T>
```

```typescript
export async function loader({ weaverse }: WeaverseComponentLoaderArgs) {
  const products = await weaverse.fetchWithCache<Product[]>(
    'https://api.example.com/products',
    {
      strategy: {
        maxAge: 60,
        staleWhileRevalidate: 600,
      },
    }
  )

  return { products }
}
```

Use `strategy`, not the Fetch API `cache` property, for Hydrogen cache-control options.

`fetchWithCache` skips Hydrogen's cache in design mode, in revision preview, and for requests to the Weaverse public API proxy (`https://api.weaverse.io/api/public/...` by default). The proxy owns the freshness of Weaverse data, so `strategy` applies to third-party URLs and to a self-hosted `WEAVERSE_HOST` that serves the API itself.

### `loadThemeSettings`

```typescript
loadThemeSettings(
  strategy?: CachingStrategy
): Promise<WeaverseThemeSettingsResponse>
```

The response can contain:

```typescript
type WeaverseThemeSettingsResponse = {
  theme?: WeaverseThemeSettings
  schema?: WeaverseThemeSchema
  publicEnv?: PublicEnv
  staticContent?: Record<string, unknown>
  merchantOverrides?: Record<string, unknown>
  _error?: string
  _loadFailed?: boolean
}
```

Return the complete response under `weaverseTheme` from the root loader so `withWeaverse` can initialize theme and translation stores:

```typescript
export async function loader({ context }: Route.LoaderArgs) {
  return {
    weaverseTheme: await context.weaverse.loadThemeSettings(),
  }
}
```

Read settings directly from the response with `response.theme`.

### `loadPage`

```typescript
loadPage(params?: {
  type?: PageType
  locale?: string
  handle?: string
  strategy?: CachingStrategy
  projectId?: string
}): Promise<WeaverseLoaderData | null>
```

#### `type`

Supported `PageType` values:

- `'*'`
- `'INDEX'`
- `'PRODUCT'`
- `'ALL_PRODUCTS'`
- `'COLLECTION'`
- `'COLLECTION_LIST'`
- `'PAGE'`
- `'BLOG'`
- `'ARTICLE'`
- `'CUSTOM'`

When omitted, the content service resolves the page from the request URL and project configuration.

#### `locale`

An optional BCP 47 locale override such as `en-US`, `sv-SE`, or `fr-CA`. The value is forwarded unchanged. When omitted, the request uses the client's `locale` argument, or `storefront.locale` when that isn't set; `loadPage()` does not implement its own URL-prefix detection or `en-us` fallback.

#### `handle`

The resource or custom-page handle used with page types such as `PRODUCT`, `COLLECTION`, `PAGE`, `BLOG`, and `ARTICLE`.

#### `projectId`

Overrides the client's resolved project ID for this request. Constructor-level `projectId` can also be a synchronous function for multi-project storefronts; an async resolver must be awaited before you create the client (see [Initialization](#initialization)).

#### `strategy`

A Hydrogen `CachingStrategy` (create one with `Cache` from `@shopify/hydrogen`). It takes effect only when the page request goes through Hydrogen's cache: requests to the default Weaverse public API proxy skip it (see [`fetchWithCache`](#fetchwithcache)). For example:

```typescript
strategy: {
  mode: 'public',
  maxAge: 3600,
  staleWhileRevalidate: 86400,
  sMaxAge: 7200,
  staleIfError: 604800,
}
```

#### Example

```typescript
export async function loader({ context, params }: Route.LoaderArgs) {
  const weaverseData = await context.weaverse.loadPage({
    type: 'PRODUCT',
    handle: params.productHandle,
    locale: 'en-US',
  })

  // `null`, or the fallback page outside design mode, means no page
  if (
    !weaverseData ||
    (weaverseData.page.id.startsWith('fallback_page_') &&
      !weaverseData.configs.isDesignMode)
  ) {
    throw new Response(null, { status: 404 })
  }

  return { weaverseData }
}
```

What `loadPage()` resolves to:

- **A page** when one is assigned to the route.
- **A fallback page** when the project loads but no page is assigned to the route. Its `page.id` starts with `fallback_page_` and it renders "Please add new section to start." It is not `null`. Answer it with a 404 on the live storefront, but keep it in design mode, where the merchant builds on it in Studio (Pilot's `validateWeaverseData` does both). An explicit "no page" signal is tracked in [Weaverse/weaverse#597](https://github.com/Weaverse/weaverse/issues/597).
- **`null`** when the Weaverse API answers 404, and, by default, when the load fails (missing or invalid project ID, network error, timeout, error status or error body). The failure is logged.
- **A rejection with [`WeaverseLoadError`](/api-reference/weaverse-load-error)** instead of `null` for a failed load when the client sets `throwPageLoadFailures: true`. Its `kind` tells an outage (`unavailable`, `invalid-response`) from a `configuration` error.

### `fetchCustomPages`

```typescript
fetchCustomPages(options?: {
  limit?: number
  locale?: string
}): Promise<CustomPageEntry[]>
```

Fetches the route metadata of every custom page assigned in the project (`path`, `lastModified`, `changeFrequency`, `priority`), for sitemap and route-generation workflows. It paginates automatically and never throws: on a failed page of results it returns the entries fetched so far.

<Warning>
  The list is not filtered by publication state, so an entry is not proof that the page is published. Apply your own publication policy before you add a route to a public sitemap. See [List Public Custom Pages](/content-api/public-custom-pages).
</Warning>

```typescript
const pages = await context.weaverse.fetchCustomPages({
  locale: 'en-US',
  limit: 100,
})
```

### `execComponentLoader`

```typescript
execComponentLoader(
  item: WeaverseComponentData
): Promise<WeaverseComponentData>
```

Runs the registered loader for one component and attaches its loader data. `loadPage()` calls this internally.

### `generateFallbackPage`

```typescript
generateFallbackPage(message: string): WeaversePageData
```

Creates the page structure used when the content response does not include page data.

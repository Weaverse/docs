# Types

<Visibility for="agents">
> **Agent note:** On `SchemaType` (alias `WeaverseComponentSchema`), `inspector` and `enabledOn` are deprecated. Generate `settings` instead of `inspector`. Do not add `enabledOn` to new components, except `enabledOn.groups` with `'body'` or `'*'` on a component that is used both as a top-level section and as a child.
</Visibility>

This page summarizes the primary public types exported by `@weaverse/hydrogen` (import them from `@weaverse/hydrogen/react-router`) and `@weaverse/schema`.

## Component Types

### `WeaverseComponent`

A component definition registered with Weaverse. The default export can be a forwarded-ref component or a function component.

```typescript
type WeaverseComponent<T extends WeaverseComponentProps = any> = {
  default:
    | ForwardRefExoticComponent<T>
    | ((props: T) => React.JSX.Element)
  schema: WeaverseComponentSchema
  loader?: (args: WeaverseComponentLoaderArgs) => Promise<unknown>
}
```

### `WeaverseComponentProps`

```typescript
interface WeaverseComponentProps<L = any> extends WeaverseElement {
  children?: React.JSX.Element[]
  className?: string
  loaderData?: L
}
```

### `WeaverseComponentSchema`

`WeaverseComponentSchema` is the current public alias for `SchemaType`. The type itself is not deprecated; only `inspector` and `enabledOn` are deprecated.

```typescript
type WeaverseComponentSchema = SchemaType

interface SchemaType {
  title: string
  type: string
  label?(data: Record<string, any>): string | null | undefined
  childTypes?: string[]
  settings?: InspectorGroup[]
  /** @deprecated Use settings. */
  inspector?: InspectorGroup[]
  presets?: {
    children?: ComponentPresets[]
    [key: string]: any
  }
  limit?: number
  enabled?: Resolvable<boolean, ComponentAvailabilityContext>
  /** @deprecated Use enabled. */
  enabledOn?: {
    pages?: PageType[]
    groups?: Array<'*' | ComponentGroup>
  }
}
```

`label` is optional and available in `@weaverse/schema` 0.17.0+ / `@weaverse/hydrogen` 5.22.0+. The method signature accepts callbacks explicitly annotated with the component's props type, such as `label: (data: HeadingProps) => data.content`; without an annotation, `data` is `Record<string, any>`. It returns synchronous plain text for the Studio outline, not a replacement for the static `title`. See [`label`](/development-guide/component-schema#label) for the example, preview-language behavior and fallback rules.

Use `createSchema()` to type-check an object against `SchemaType` and enable development-time diagnostics:

```tsx
import { createSchema } from '@weaverse/hydrogen/react-router'

export const schema = createSchema({
  type: 'hero-banner',
  title: 'Hero Banner',
  settings: [],
})
```

`createSchema()` returns the original schema immediately. Outside production it asynchronously lazy-loads Zod and logs validation issues as warnings; validation and import failures do not throw through the call. Production builds skip this validation path.

## Inspector Types

The public types retain “Inspector” in their names for compatibility, but new schemas should use the `settings` property.

### `InspectorGroup`

```typescript

}
```

### `BasicInput`

```typescript
interface BasicInput {
  type: InputType
  name: string
  label?: string
  placeholder?: string
  helpText?: string
  configs?: ConfigsProps
  defaultValue?: unknown
  shouldRevalidate?: boolean
  sensitive?: boolean
```

String conditions remain supported but are deprecated; prefer a function.

## Theme Types

### `WeaverseThemeSettings`

```typescript
type WeaverseThemeSettings = {
  [key: string]: any
}
```

### `WeaverseThemeSchema`

```typescript
type WeaverseThemeSchema = {
  info: {
    name: string
    version: string
    author: string
    authorProfilePhoto: string
    documentationUrl: string
    supportUrl: string
  }
  /** @deprecated Use settings. */
  inspector?: InspectorGroup[]
  /** Store-wide Media Manager filtering. Not merchant-editable. */
  media?: {
    excludeFilenamePrefixes?: string[]
    excludeProductFiles?: boolean
  }
  settings?: InspectorGroup[]
  routes?: ThemeRoutes
  outline?: ThemeOutline
  i18n?: {
    urlStructure: 'url-path' | 'subdomain' | 'top-level-domain'
    defaultLocale: WeaverseI18n
    shopLocales: WeaverseI18n[]
    staticContent?: Record<string, unknown>
    translation?: boolean
  }
}
```

`media` sets what the Media Manager gallery hides for every picker in the theme. It is a sibling of
`settings` rather than an entry inside it, because `settings` renders as merchant-editable controls and
these rules are meant to be fixed by the theme author. An `image` or `video` input can override them for
its own picker — see [Filtering the Media Manager gallery](/development-guide/input-settings#filtering-the-media-manager-gallery).

`routes` declares URL patterns that Studio uses for page navigation and URL picking. It is available as a typed field in `@weaverse/hydrogen` 5.23.0+ and on `WeaverseNextThemeSchema` in `@weaverse/hydrogen/next` (`@weaverse/hydrogen` 6.0.0+). See [Declare Theme Routes for Studio](/features/custom-routing#declare-theme-routes-for-studio) for configuration, the Forward example, and fallback behavior.

`outline` lists theme settings groups in Studio's Page Outline, keyed by area. Values are settings `group` names, matched case-insensitively. `header` and `aside` render above the page sections, in that order; every other key, `footer` included, renders below them in declaration order:

```typescript
type ThemeOutline = {
  header?: string[]
  aside?: string[]
  footer?: string[]
} & Record<string, string[]>

// Example
outline: {
  header: ['Scrolling announcements', 'Header'],
  footer: ['Footer'],
  'popups-and-newsletter': ['Newsletter Popup'],
}
```

`ThemeOutline` is exported by `@weaverse/schema` 0.20.0+; `outline` is typed on `WeaverseThemeSchema` and `WeaverseNextThemeSchema`. To let Studio highlight and select a group's DOM, spread `getThemeElementProps('Header')` on the element that renders it (it adds a `data-wv-theme-id` attribute). `@weaverse/hydrogen` exposes `getThemeElementProps`, `getThemeElementId` and `THEME_ELEMENT_ATTRIBUTE` only from `@weaverse/hydrogen/internal`, which isn't a stable API; import them from `@weaverse/schema` instead. Read the current selection with [`useStudioSelection`](/api-reference/use-studio-selection).

### `ThemeRoutes` and `ThemeRoutePageType`

Exported by `@weaverse/schema` 0.18.0+. `@weaverse/hydrogen` 6 doesn't re-export them from any entry, including `@weaverse/hydrogen/next`; import them from `@weaverse/schema`:

```typescript
type ThemeRoutePageType = Exclude<PageType, '*' | 'CUSTOM'>
type ThemeRoutes = Partial<Record<ThemeRoutePageType, string>>
```

Each optional entry maps a supported [page type](#page-types) to an absolute path with static segments and whole `:handle` or `:blog` segments. `CUSTOM` pages carry their own path; `*` is not a route key. TypeScript checks the keys, while pattern values remain strings. See the guide's [supported keys and patterns](/features/custom-routing#supported-keys-and-patterns) for the grammar and parameter meanings.

## Component Availability

The canonical types are exported by `@weaverse/schema`. `@weaverse/hydrogen` 6 re-exports only `createSchema`, `SchemaType`, `BasicInput`, `InspectorGroup` and `PageType` from it:

```typescript
interface ComponentAvailabilityContext {
  group: 'body' | 'header' | 'footer'
  page: {
    id: string
    type: PageType
    handle: string
    locale: string
  }
}

type ComponentGroup = 'body' | 'header' | 'footer'

type Resolvable<T, Context> =
  | T
  | ((context: Context) => T)
```

Use `enabled` for static or synchronous conditional availability:

```typescript
const schema = createSchema({
  type: 'product-details',
  title: 'Product details',
  enabled: ({ page, group }) =>
    page.type === 'PRODUCT' && group === 'body',
})
```

`enabledOn` remains supported for backward compatibility but is deprecated. Avoid relying on undocumented behavior for thrown errors, promises, RPC serialization, or existing instances; these semantics are not part of the public SDK contract.

`enabled` controls insertion availability only. A type listed in any component's `childTypes` appears in the root **Add Section** picker only when its `enabledOn.groups` contains `'body'` or `'*'`, even if `enabled` returns `true`. Keep that field on dual-use components during migration; see [Standalone and Nested Components](/development-guide/component-schema#standalone-and-nested-components).

## Usage Example

```tsx
import type { Ref } from 'react'
import { Cache, gql } from '@shopify/hydrogen'
import {
  createSchema,
  type WeaverseComponentLoaderArgs,
  type WeaverseComponentProps,
} from '@weaverse/hydrogen/react-router'

type Product = {
  id: string
  title: string
}

type HeroLoaderData = {
  featuredProducts: Product[]
}

type HeroBannerProps = WeaverseComponentProps<HeroLoaderData> & {
  heading: string
  subheading?: string
  ref?: Ref<HTMLElement>
}

function HeroBanner({
  heading,
  subheading,
  loaderData,
  ref,
  ...rest
}: HeroBannerProps) {
  return (
    <section ref={ref} {...rest}>
      <h1>{heading}</h1>
      {subheading && <p>{subheading}</p>}
      {loaderData?.featuredProducts.map((product) => (
        <div key={product.id}>{product.title}</div>
      ))}
    </section>
  )
}

const schema = createSchema({
  type: 'hero-banner',
  title: 'Hero Banner',
  settings: [
    {
      group: 'Content',
      inputs: [
        {
          type: 'text',
          name: 'heading',
          label: 'Heading',
          defaultValue: 'Welcome to our store',
        },
      ],
    },
  ],
})

const FEATURED_PRODUCTS_QUERY = gql(`
  query featuredProducts($country: CountryCode, $language: LanguageCode)
  @inContext(country: $country, language: $language) {
    products(first: 4) { nodes { id title } }
  }
`)

async function loader({
  weaverse,
}: WeaverseComponentLoaderArgs): Promise<HeroLoaderData> {
  const { data } = await weaverse.storefront.graphql(FEATURED_PRODUCTS_QUERY, {
    cache: Cache.short(),
  })

  return {
    featuredProducts: data?.products.nodes ?? [],
  }
}

export default HeroBanner
export { loader, schema }
```

## Type Extensions

A Hydrogen app augments its load context and environment in `env.d.ts`. Hydrogen 2026.10 has no `HydrogenEnv`, so `Env` extends the SDK's `WeaverseEnv`, and the context type comes from the app's own `createAppContext()` (see the [v6 migration guide](/migration-advanced/v6-migration#step-4-build-the-app-context-yourself)):

```typescript
import type { WeaverseEnv } from '@weaverse/hydrogen/react-router'
import type { AppContext } from './app/.server/context' // includes `weaverse: WeaverseClient`

declare module 'react-router' {
  interface AppLoadContext extends AppContext {}
  interface RouterContextProvider extends AppContext {}
}

declare global {
  interface Env extends WeaverseEnv {
    SESSION_SECRET: string
    PUBLIC_STORE_DOMAIN: string
    WEAVERSE_PROJECT_ID: string
    WEAVERSE_HOST?: string
    WEAVERSE_API_KEY?: string
  }
}
```

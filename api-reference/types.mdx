# Types

<Visibility for="agents">
> **Agent note:** On `SchemaType` (alias `HydrogenComponentSchema`), `inspector` and `enabledOn` are deprecated. Generate `settings` instead of `inspector`. Do not add `enabledOn` to new components, except `enabledOn.groups` with `'body'` or `'*'` on a component that is used both as a top-level section and as a child.
</Visibility>

This page summarizes the primary public types exported by `@weaverse/hydrogen` and `@weaverse/schema`.

## Component Types

### `HydrogenComponent`

A component definition registered with Weaverse. The default export can be a forwarded-ref component or a function component.

```typescript
type HydrogenComponent<T extends HydrogenComponentProps = any> = {
  default:
    | ForwardRefExoticComponent<T>
    | ((props: T) => React.JSX.Element)
  schema: HydrogenComponentSchema
  loader?: (args: ComponentLoaderArgs) => Promise<unknown>
}
```

### `HydrogenComponentProps`

```typescript
interface HydrogenComponentProps<L = any> extends WeaverseElement {
  children?: React.JSX.Element[]
  className?: string
  loaderData?: L
}
```

### `HydrogenComponentSchema`

`HydrogenComponentSchema` is the current public alias for `SchemaType`. The type itself is not deprecated; only `inspector` and `enabledOn` are deprecated.

```typescript
type HydrogenComponentSchema = SchemaType

interface SchemaType {
  title: string
  type: string
  label?(data: Record<string, any>): string | null | undefined
  childTypes?: string[]
  settings?: InspectorGroup[]
  /** @deprecated Use settings. */
  inspector?: InspectorGroup[]
  presets?: {
    children?: ComponentPresets[]
    [key: string]: any
  }
  limit?: number
  enabled?: Resolvable<boolean, ComponentAvailabilityContext>
  /** @deprecated Use enabled. */
  enabledOn?: {
    pages?: PageType[]
    groups?: Array<'*' | ComponentGroup>
  }
}
```

`label` is optional and available in `@weaverse/schema` 0.17.0+ / `@weaverse/hydrogen` 5.22.0+. The method signature accepts callbacks explicitly annotated with the component's props type, such as `label: (data: HeadingProps) => data.content`; without an annotation, `data` is `Record<string, any>`. It returns synchronous plain text for the Studio outline, not a replacement for the static `title`. See [`label`](/development-guide/component-schema#label) for the example, preview-language behavior and fallback rules.

Use `createSchema()` to type-check an object against `SchemaType` and enable development-time diagnostics:

```tsx
import { createSchema } from '@weaverse/hydrogen'

export const schema = createSchema({
  type: 'hero-banner',
  title: 'Hero Banner',
  settings: [],
})
```

`createSchema()` returns the original schema immediately. Outside production it asynchronously lazy-loads Zod and logs validation issues as warnings; validation and import failures do not throw through the call. Production builds skip this validation path.

## Inspector Types

The public types retain “Inspector” in their names for compatibility, but new schemas should use the `settings` property.

### `InspectorGroup`

```typescript
interface InspectorGroup {
  group: string
  inputs: (BasicInput | HeadingInput)[]
}
```

### `BasicInput`

```typescript
interface BasicInput {
  type: InputType
  name: string
  label?: string
  placeholder?: string
  helpText?: string
  configs?: ConfigsProps
  defaultValue?: unknown
  shouldRevalidate?: boolean
  sensitive?: boolean
  condition?: string | Function
}
```

String conditions remain supported but are deprecated; prefer a function.

### `HeadingInput`

```typescript
interface HeadingInput {
  type: 'heading'
  label: string
  [key: string]: unknown
}
```

## Theme Types

### `HydrogenThemeSettings`

```typescript
type HydrogenThemeSettings = {
  [key: string]: any
}
```

### `HydrogenThemeSchema`

```typescript
type HydrogenThemeSchema = {
  info: {
    name: string
    version: string
    author: string
    authorProfilePhoto: string
    documentationUrl: string
    supportUrl: string
  }
  /** @deprecated Use settings. */
  inspector?: InspectorGroup[]
  /** Store-wide Media Manager filtering. Not merchant-editable. */
  media?: {
    excludeFilenamePrefixes?: string[]
    excludeProductFiles?: boolean
  }
  settings?: InspectorGroup[]
  routes?: ThemeRoutes
  i18n?: {
    urlStructure: 'url-path' | 'subdomain' | 'top-level-domain'
    defaultLocale: WeaverseI18n
    shopLocales: WeaverseI18n[]
    staticContent?: Record<string, unknown>
    translation?: boolean
  }
}
```

`media` sets what the Media Manager gallery hides for every picker in the theme. It is a sibling of
`settings` rather than an entry inside it, because `settings` renders as merchant-editable controls and
these rules are meant to be fixed by the theme author. An `image` or `video` input can override them for
its own picker — see [Filtering the Media Manager gallery](/development-guide/input-settings#filtering-the-media-manager-gallery).

`routes` declares URL patterns that Studio uses for page navigation and URL picking. It is available as a typed field in `@weaverse/hydrogen` 5.23.0+ and on `WeaverseNextThemeSchema` in stable `@weaverse/next` 1.0.0+. See [Declare Theme Routes for Studio](/features/custom-routing#declare-theme-routes-for-studio) for configuration, the Forward example, and fallback behavior.

### `ThemeRoutes` and `ThemeRoutePageType`

Exported by `@weaverse/schema` 0.18.0+ and re-exported by `@weaverse/hydrogen` and `@weaverse/next`:

```typescript
type ThemeRoutePageType = Exclude<PageType, '*' | 'CUSTOM'>
type ThemeRoutes = Partial<Record<ThemeRoutePageType, string>>
```

Each optional entry maps a supported [page type](#page-types) to an absolute path with static segments and whole `:handle` or `:blog` segments. `CUSTOM` pages carry their own path; `*` is not a route key. TypeScript checks the keys, while pattern values remain strings. See the guide's [supported keys and patterns](/features/custom-routing#supported-keys-and-patterns) for the grammar and parameter meanings.

## Component Availability

The canonical types are exported by `@weaverse/schema` and re-exported by `@weaverse/hydrogen`:

```typescript
interface ComponentAvailabilityContext {
  group: 'body' | 'header' | 'footer'
  page: {
    id: string
    type: PageType
    handle: string
    locale: string
  }
}

type ComponentGroup = 'body' | 'header' | 'footer'

type Resolvable<T, Context> =
  | T
  | ((context: Context) => T)
```

Use `enabled` for static or synchronous conditional availability:

```typescript
const schema = createSchema({
  type: 'product-details',
  title: 'Product details',
  enabled: ({ page, group }) =>
    page.type === 'PRODUCT' && group === 'body',
})
```

`enabledOn` remains supported for backward compatibility but is deprecated. Avoid relying on undocumented behavior for thrown errors, promises, RPC serialization, or existing instances; these semantics are not part of the public SDK contract.

`enabled` controls insertion availability only. A type listed in any component's `childTypes` appears in the root **Add Section** picker only when its `enabledOn.groups` contains `'body'` or `'*'`, even if `enabled` returns `true`. Keep that field on dual-use components during migration; see [Standalone and Nested Components](/development-guide/component-schema#standalone-and-nested-components).

## Usage Example

```tsx
import type { Ref } from 'react'
import {
  createSchema,
  type ComponentLoaderArgs,
  type HydrogenComponentProps,
} from '@weaverse/hydrogen'

type Product = {
  id: string
  title: string
}

type HeroLoaderData = {
  featuredProducts: Product[]
}

type HeroBannerProps = HydrogenComponentProps<HeroLoaderData> & {
  heading: string
  subheading?: string
  ref?: Ref<HTMLElement>
}

function HeroBanner({
  heading,
  subheading,
  loaderData,
  ref,
  ...rest
}: HeroBannerProps) {
  return (
    <section ref={ref} {...rest}>
      <h1>{heading}</h1>
      {subheading && <p>{subheading}</p>}
      {loaderData?.featuredProducts.map((product) => (
        <div key={product.id}>{product.title}</div>
      ))}
    </section>
  )
}

const schema = createSchema({
  type: 'hero-banner',
  title: 'Hero Banner',
  settings: [
    {
      group: 'Content',
      inputs: [
        {
          type: 'text',
          name: 'heading',
          label: 'Heading',
          defaultValue: 'Welcome to our store',
        },
      ],
    },
  ],
})

async function loader({
  weaverse,
}: ComponentLoaderArgs): Promise<HeroLoaderData> {
  const { products } = await weaverse.storefront.query(
    'FEATURED_PRODUCTS_QUERY'
  )

  return {
    featuredProducts: products.nodes,
  }
}

export default HeroBanner
export { loader, schema }
```

## Type Extensions

A Hydrogen app can augment its load context and environment:

```typescript
import type { HydrogenEnv } from '@shopify/hydrogen'
import type { WeaverseClient } from '@weaverse/hydrogen'
import type { createHydrogenRouterContext } from './app/.server/context'

declare module 'react-router' {
  interface AppLoadContext
    extends Awaited<ReturnType<typeof createHydrogenRouterContext>> {
    weaverse: WeaverseClient
  }
}

declare global {
  interface Env extends HydrogenEnv {
    WEAVERSE_PROJECT_ID: string
    WEAVERSE_HOST?: string
    WEAVERSE_API_KEY: string
  }
}
```
